# 問題の作り方

問題は Claude Code のサブエージェントで作り、`src/data/questions/` に JSON で保存する。アプリは保存された問題だけを出す。

## 流れ

1. **範囲を決める**：`npm run questions:check` で単元・テーマごとの問題数を見て、手薄な単元またはテーマを選ぶ
2. **作成役**（単元・テーマごとに1エージェント、並列で動かす）に渡すもの
   - 単元またはテーマの名前と、ID の接頭辞（例：`u03-`、`t-era-sense-`）
   - そのファイルにすでにある問題の、問題文と正解の一覧（重複を避けるため）
   - `docs/exam-research.md` の傾向と、下の「作成の決まり」
   - 問題集の分析メモ（`sources/analysis/` があれば）
3. **検証役**（作成役とは別のエージェント）は、正解を伏せた問題を受験者として解く。そのうえで次のものを報告する
   - 自分の答えが想定の正解と違う問題
   - 正解が2つ以上ありうる問題
   - 事実・年代に疑いがある問題
   - 説明が誤っている問題
4. **直す**：報告された問題は、根拠を確かめて直す。確信が持てなければ捨てる
5. **機械チェック**：`npm run questions:check` を通す（形式、重複、配分）
6. **コミット**：単元・テーマごとのファイル（`u03.json`、`t-era-sense.json`）として保存する

## 作成の決まり

- 4択で、正解は1つだけ。「すべて正しい」「上記以外」のような選択肢は使わない（表示時に並べ替えるため）
- 高校世界史探究の教科書の太字〜準太字レベルを中心にし、難しさ3は用語集の頻度が低めのものにする
- 誤りの選択肢は、本当に誤りであることが一つの事実で言えるものにする。主なすり替え方
  - 時代がずれている（別の世紀・別の王朝の出来事）
  - 人物・王朝・地名・著作の取り違え
  - 因果や順序の逆転
- `explanation` は全選択肢に付ける。1〜2文で、正解は根拠を、誤りは「どこが違うか・正しくは何か」を書く
- 年号は確かなものだけを使う。諸説ある年代は問わない
- 問題集の問題文・選択肢をそのまま、または語句を少し変えただけで写さない。問題集は傾向と頻出語句の参考にする
- 形式の配分の目安：`incorrect` 30% / `correct` 25% / `term` 25% / `chronology` 10% / `combination` 10%
- `id` は接頭辞 + 3桁の通し番号。一度付けた ID は変えない（解答の記録が参照するため）。問題を捨てた番号は再利用しない
